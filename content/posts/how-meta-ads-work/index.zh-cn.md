打开 Ads Manager 后，广告主可以选择 Campaign Objective、设置预算和受众、上传素材，再指定希望 Meta 优化的结果。后台把投放呈现为一组可以操作的设置，但广告上线之后，系统如何决定进入广告获得哪些曝光机会、把广告展示给谁，以及用多少预算争取这些展示呢？

要理解这些问题，需要明确的是：广告主购买的并不是一批提前固定的人群或版位。每当 Facebook、Instagram 或 Meta 的其他广告版位出现展示机会时，系统都会从当时符合条件的广告中筛选候选项，预测不同广告展示给当前用户后可能产生的结果，再通过竞价与排序决定最终交付。预算、出价、受众、素材和 Optimization Event，都会影响这个实时决策过程。

[Meta](https://engineering.fb.com/2024/12/02/production-engineering/meta-andromeda-advantage-automation-next-gen-personalized-ads-retrieval-engine/) 已经公开说明，其广告推荐系统采用多阶段结构。系统先从数量庞大的广告中召回较相关的候选项，再使用更复杂的模型预测这些广告对用户和广告主可能产生的价值，最后选择展示结果。随着 Advantage+ 和 AI 驱动的广告产品发展，受众扩展、预算分配、版位和素材组合中的更多决策也开始由系统完成。

## 从广告请求到最终展示：一次广告交付经历了什么

当用户刷新 Feed、浏览 Stories 或观看 Reels，页面中可能出现一个可供广告展示的位置。对广告系统来说，这会形成一次广告请求。系统需要在极短时间内判断当前有哪些广告可以参与、哪些广告更可能适合这位用户，以及最终展示哪一条。

一次广告交付可以简化为下面几个环节：
```text
出现广告展示机会
→ 筛选符合条件的广告
→ 召回相关候选广告
→ 预测用户采取目标行为的可能性
→ 计算广告的 Total Value 并完成排序
→ 结合预算与投放节奏完成交付
→ 用户行为形成新的反馈数据
```

这是一张用于理解投放的简化地图，不代表 Meta 向外公布了每一项内部处理步骤，也不表示所有 Campaign 都由完全相同的模型处理。它的价值在于帮助投手定位：某项设置究竟改变了候选广告的范围、预测目标、竞价能力，还是系统后续能够获得的反馈。

### 第一步：形成符合投放条件的广告集合

并非所有正在运行的广告都能参与每一次展示机会。系统首先需要判断一条广告在当前情境下是否具备交付资格，常见条件包括：

- 用户是否处于广告允许触达的地区、年龄和其他 Audience Controls 范围内。
- 当前页面和设备是否属于广告可以使用的 Placement。
- Campaign、Ad Set 和 Ad 是否处于启用状态，并通过广告审核。
- 投放时间、预算、出价策略和 Billing 状态是否允许继续交付。
- 特殊广告类别、法律政策与用户隐私选择是否形成额外限制。

这里可以把受众设置理解为一道边界与信号的组合。地区、最低年龄和服务资格等条件通常属于不可突破的约束；兴趣、Custom Audience、Lookalike 或 Advantage+ Audience 中的建议，则可能帮助系统识别优先探索的方向。具体哪些条件可以扩展，要以当前产品设置和官方说明为准。

因此，“Audience Size 很大”只说明理论上存在较大的可触达范围，无法保证系统会平均覆盖其中每一类人。系统还要继续判断哪些用户更有可能完成广告主指定的目标，以及哪些展示机会可以在预算和出价条件下产生更高价值。

### 第二步：从大量合格广告中召回候选项

对于某一次展示机会，潜在合格广告的数量可能非常庞大。如果直接用最复杂的模型逐一计算，系统很难在用户正常浏览页面所允许的时间内返回结果。因此，广告推荐通常需要先进行 Candidate Retrieval，把大规模广告集合缩小为更少、更相关的候选项。

Meta 在介绍 Andromeda 时表示，Retrieval 是其多阶段广告推荐系统的第一步，负责把数以千万计的广告候选缩小到数千个，后续阶段再使用规模更大、更加复杂的 Ranking Model 进行预测和筛选。这个过程也说明，广告能否获得展示，首先取决于它是否进入了相关候选集合，随后才进入更精细的价值比较。

投手无法查看某条广告参加了多少次 Retrieval，也无法为单次用户请求手动指定候选名单。但以下设置会直接或间接改变系统拥有的选择空间：

| 投放设置 | 对候选空间的可能影响 |
| --- | --- |
| 地区、年龄及合规限制 | 排除不具备服务资格或不允许触达的用户 |
| Audience Controls 与受众建议 | 确定硬性边界，并向系统提供初始方向 |
| Placement | 决定广告可以参与哪些版位的展示机会 |
| 素材格式 | 决定广告是否适合相应版位和展示环境 |
| Campaign Objective 与 Performance Goal | 告诉系统需要围绕什么结果寻找机会 |
| 预算和出价策略 | 影响系统可以参与和赢得哪些成本水平的机会 |

限制越多，系统可选择的展示机会通常越少；开放更多空间也不会自动保证结果更好。对于受到牌照、服务地区或年龄要求限制的 Fintech App，必要的业务和合规边界仍然需要明确保留。在允许范围内，系统拥有多大的探索空间，则需要结合事件质量、素材覆盖和预算判断。

### 第三步：预测广告展示后可能发生什么

候选广告进入后续排序阶段后，系统需要回答一个核心问题：如果把某条广告展示给当前用户，他采取广告主期望行为的可能性有多大？这个预测通常被概括为 Estimated Action Rate。

“期望行为”由广告主选择的投放目标决定。围绕 Link Click 优化时，系统寻找更可能点击的人；围绕 App Install 优化时，它更关注安装概率；围绕 Purchase、KYC Complete 或其他深层 Event 优化时，预测目标也随之改变。因此，同一个用户对不同 Optimization Event 可能具有完全不同的预测价值。

Meta 的公开资料显示，广告推荐模型会利用用户行为和广告相关信号进行预测，而且近年的系统更加重视行为发生的顺序和时间。[Meta 关于广告 Sequence Learning 的说明](https://engineering.fb.com/2024/11/19/data-infrastructure/sequence-learning-personalized-ads-recommendations/)介绍了系统如何通过用户行为序列形成更丰富的兴趣和广告偏好表示。2026 年公布的[多阶段广告 Ranking 架构](https://engineering.fb.com/2026/08/05/ml-applications/from-user-sequences-to-scaling-laws-a-multi-stage-architecture-for-metas-ads-ranking/)则进一步说明，离线生成的用户表示会与实时广告候选信号结合，用于在线排序。

这些公开信息能够帮助我们理解预测的方向，但不足以列出 Meta 当前使用的全部特征。投手也不需要知道某位用户的具体预测分数。更重要的是理解以下关系：

- Optimization Event 改变了系统需要预测的行为。
- 数据回传让系统观察到哪些广告展示最终产生了目标行为。
- 素材及其历史反馈会影响系统判断广告与用户是否匹配。
- 事件过少、延迟过长或定义不稳定，会减少模型可以利用的有效反馈。

以 Fintech App 为例，围绕 Install 优化的 Campaign 可能找到大量愿意下载金融类 App 的用户，但他们不一定愿意完成 KYC 或首次入金。改用 KYC Complete 后，系统需要学习另一种行为概率。这个信号更接近业务价值，同时也可能数量更少、回传更慢。优化事件的选择因此会同时改变系统寻找的人，以及系统学习这类人的难度。

### 第四步：通过 Auction 比较广告的 Total Value

在一次展示机会中，候选广告最终还需要通过 Auction 进行比较。Meta 公布的核心逻辑可以表示为：

```text
Total Value = Advertiser Bid × Estimated Action Rate + Ad Quality
```

其中：

- **Advertiser Bid** 表示广告主为目标结果投入的价值。使用自动出价时，这项判断由系统结合预算和 Bid Strategy 完成，并不要求投手为每次展示手动报价。
- **Estimated Action Rate** 是系统预测当前用户在看到广告后完成目标行为的可能性。
- **Ad Quality** 用于考虑用户对广告体验和质量的判断，可能受到用户反馈以及低质量属性等因素影响。

Meta 在其关于广告系统公平性的官方说明中，同样把 Advertiser Bid、Estimated Action Rate 和 Ad Quality 列为 Total Value 的三个核心组成部分，并说明最高 Total Value 的广告更有可能赢得 Auction。[Meta 对广告 Auction 与 Total Value 的说明](https://ai.meta.com/blog/advertising-fairness-variance-reduction-system-vrs/)

这个公式用于表达排序逻辑，不能当作 Ads Manager 中可以复算的财务公式。广告主看不到每次 Auction 的完整输入和分值，Meta 也可能在具体系统中加入 Pacing、完整性保护、公平性与其他约束。它至少解释了一个重要现象：出价最高的广告不一定赢得展示。较高的行动概率和更好的广告质量，也可能提高广告在竞价中的整体价值。

它还解释了为什么素材、信号和出价需要放在同一套系统中理解。提高 Bid 只能改变其中一部分；素材能否让目标用户产生响应，会影响预测与质量；Optimization Event 和数据回传则影响系统在学习什么、能够看到什么结果。

### 第五步：预算与 Pacing 决定何时参与和花费

赢得某一次 Auction 不代表系统会立即、均匀地用完全部预算。Meta 还需要在投放周期内安排参与 Auction 的节奏，也就是常被称为 Pacing 的过程。系统会考虑剩余预算、剩余时间、可获得的展示机会、预期成本和 Bid Strategy，在当前花费与后续机会之间进行分配。

这也是 Daily Budget 不会被机械地切分到每个小时、每个用户或每条广告上的原因。一天中的竞争环境和转化机会持续变化，系统可能在某些时段花费更快，在另一些时段保持谨慎。使用 Campaign Budget 时，预算还会在不同 Ad Set 之间动态分配。

从投手角度看，Pacing 可以帮助解释几类情况：

- Campaign 有充足预算，却因为 Bid 或 Cost Control 较严格而花不出去。
- 某个 Ad Set 获得较多预算，因为系统预测它在当前机会中更容易产生目标结果。
- 短时间内花费和 CPA 出现波动，但完整投放周期的结果相对稳定。
- 预算突然增加后，系统需要进入更多或成本不同的 Auction，边际结果随之变化。

具体的 Pacing 算法并未完整公开，因此不应把某个小时的花费曲线解释成一条确定的平台规则。投手可以观察预算利用率、成本、结果量和时间分布，判断限制更可能来自机会不足、竞价约束、受众边界还是数据反馈。

### 第六步：用户行为回到系统，成为下一轮预测的反馈

广告完成展示后，用户可能忽略广告，也可能点击、安装、注册、购买或完成更深层的业务行为。Meta 能够观察到的平台行为，以及广告主通过 Pixel、App SDK、MMP 或 CAPI 回传的 Event，会形成后续优化可以利用的反馈。

这使广告交付成为持续更新的循环：系统根据已有信息进行预测和分配，观察实际结果，再调整未来对相似用户、素材与展示机会的判断。Learning Phase 反映的正是这种反馈积累和交付探索过程的一部分，后文会单独讨论。

反馈并不会让系统自动理解完整的商业价值。如果 Campaign 优化 Install，它会从“哪些人容易安装”的结果中学习；如果真正有价值的行为是 First Transaction，广告主仍然需要把安装后的漏斗和业务结果纳入判断，并在数据条件允许时提供更接近价值的信号。

至此，一次广告展示可以被理解为一条连续的决策链：资格条件划定边界，Retrieval 缩小候选范围，Prediction 估计行为概率，Auction 比较整体价值，Pacing 安排预算与参与节奏，用户结果再回到系统形成反馈。后续所有投放设置，实际都在改变这条链路中的一个或多个环节。
